# 任务：GitHub 周热榜双期视频（github-trending-weekly）

> 每周五北京时间 17:00 左右启动。
> 在装有现有管线的机器上执行，工作根目录 `E:\Repository\video-code`。一次任务产出**两期独立成片**，共享同一份研究。

## 0. 总原则

- 榜单口径不偷换；事实与观点分开；素材可追溯；交付按实际完成情况说明，不把失败藏起来。
- 先守住选题口径，再复用制作管线；按真实数量和真实证据讲述。
- 新建当周目录，复用上一周结构，**不覆盖历史产物**。

## 1. 周次与目录

- 周次 = 启动日所在 ISO 周历周（周一为一周之始）。目录：`video-code/github-trending-<year>w<week>/`。
- 子目录：`ai/`（Agent/AI 期产物）、`other/`（非 AI 类期产物）、`raw/`（榜单原始依据）。
  `other` 只是内部目录名，**对外一律称"非 AI 类项目"**，标题、口播、封面、字幕、简介、交付文字中名称保持一致。
- 参考实例：`video-code/github-trending-2026w47/`（包含`ai/`、`other/`、`raw/`、`research.md`、`trending_weekly.json`、`make_covers.py`等）。

## 2. 榜单获取（一次快照，两期共用）

1. 抓取 `https://github.com/trending?since=weekly`（All languages）完整可用列表，保留：
   - 原始 HTML → `raw/trending_weekly.html`；抓取时刻 → `raw/snapshot_time.txt`（北京时间，附 PST 对照）。
   - 每个入选项目的 API 元数据 → `raw/meta_<owner>_<repo>.json`，README 原文 → `raw/README_<owner>_<repo>.md`。
2. 记录页面条目数；与近几周量级对比，异常时说明，不换榜。

## 3. 分类与选题口径（互斥、保序、不凑数）

| 规则 | 口径 |
|---|---|
| 逐项判定 | 以 README / 官方文档中的**主用途**为准，不凭名称、标签或 "AI" 关键词。Agent/AI 类 = 智能体、模型、训练/推理、AI 应用及主要为 AI 设计的工具；通用项目仅带 AI 集成的不归入。 |
| 互斥 | 每个项目只进一类；第二类对外统一称"非 AI 类项目"。 |
| 保序 | 各组保留周榜页面顺序取前五；**不**按周新增星重排，**不**把总榜前五拆成两期。 |
| 不足照实 | 一类少于五项就做实际项数并解释缺项；不补凑、不改用其他榜单、不伪造第五项。 |

- 完整分类表（页序、仓库、本周星、总星、语言、分类、理由）写入 `research.md`，含未入选项目。
- 呈现按 **#5 → #1 倒序**展开；不足五项从实际末位开始；片中不口播"从第五名开始"。
- 星数、名次取快照时刻的页面值（不是事后 API 实时值），差异只记录不推断；不以星数增速认定刷星。

## 4. 每个项目的研究卡片

- 本周星、总星、语言、许可、创建时间；查 README、官方文档、发布信息与真实社区来源；无法确认的标"未核实"。
- 解释高层架构：哪些组件协作、为何这样设计；用真实应用场景说明价值。
- 搜集官方演示图 / GIF / 录屏，来源逐条记入当期 `assets.md`。
- 异常或争议只记录证据与不确定性，不下结论。
- **安全**：不执行陌生仓库的二进制或安装脚本；研究全程只读。

## 5. 脚本（少科普，多讲设计）

- 片头一句日期开场，不讲快照时间与抓取过程；自然衔接项目，结尾回顾。每期约 5 分钟。
- 讲组件协作、设计取舍、具体用例；不讲文件树或 CLI 操作；不科普 skill、plugin、MCP、transformer 等基础概念。
- 分类数量与统计放图表，不逐个念数字；启示融入项目分析，不设僵硬"启示"段落。
- 画面风格可参考往期视频。

## 6. 制作管线（每期独立跑一遍）

文件链（`ai/` 与 `other/` 各一套，后缀 `_ai` / `_other`）：

```
script_<期>.py（旁白） → tts_<期>.py（配音，产出 timing_<期>.json + audio_<期>/）
→ scenes_<期>.py + render_<期>.sh（Manim，逐场景按顺序渲染）
→ peek.py（每场景抽帧检查） → assemble_<期>.py（合成）
→ checkcut（成片抽帧） → make_covers.py（封面）
```

- **画面**：Manim 1080p30（1920×1080），GitHub 深色科技风。
- **配音**：MiniMax 中国站 `speech-2.8-hd`，音色 `male-qn-jingying`（精英青年），speed 1.1，可通过已登录的 mmx-cli 进行调用；按场景段落合成，用词级时间戳对齐画面与字幕；保证语音的间隔与语义的间隔对齐，避免出现同一短语内的词汇间隔长而不同语句的间隔短；多音字与英文名用 `pronunciation_dict` 校正（如"重新"读 chóng）；整片响度约 -16 LUFS。
- **字幕**：烧录约 60px 中文 ASS；同时生成独立 SRT；只在句读标点处断行，不在顿号或列表中间断行。
- **合成**：ffmpeg 拼接、x264 crf20、faststart。
- **逐场景视觉检查**：每场景抽帧查重叠、裁切、拥挤，发现问题修复后重渲染，再合成成片。
- **封面**：三尺寸 1920×1080、1440×1080、1080×1440；系列风格 + 日期 + 类别 + 头像 + 排名 + 短中文说明 + 关键指标，第一名突出；全尺寸与缩略图都查可读性。
- **环境**：conda 环境`video`，位于`E:\Runtime\anaconda\envs\video`，包含manim、Pillow等；若有缺失依赖则在该环境中进行修复。

## 7. 交付（在本聊天中按期交付）

每期完整包：`github_trending_ai_w<ww>.mp4` / `github_trending_other_w<ww>.mp4`（各 1 个）+ 对应 `.srt` + 三张封面 + `description.txt`。两期附件、名单、简介严格分开，不混写。

交付顺序：① 先附 MP4；② 简短中文名单，每条带可点击链接，标明周新增星与用途；③ 说明必要局限并附三张封面；④ 最后单独代码块贴简介；SRT 保留可交付。若只有一期成功，先交付成功的一期并指出另一期缺什么。

`description.txt` 模板：

```
GitHub Agent/AI 周热榜 Top 5（<年份> 年第 <周次> 周 · <日期>）｜<一句 hook>

#5 <owner/repo>：<一句总结>
<完整 URL>
（按实际数量续写 #4…#1，不足五项不伪造）

数据来源：GitHub Trending 周榜（https://github.com/trending?since=weekly），名次为按页面顺序筛选 <分类口径> 后的类内前五。
```

最后提交 git，commit message 遵循标准规范；只提交文本文件、代码，避免提交二进制文件。

## 8. 验收（未完成不得写成已完成）

- [ ] 榜单：同一可用周榜、分类互斥、各组保留原序；不足五项照实说明。
- [ ] 研究：关键用途、设计和场景有来源；自报与独立评测有区分；不确定性已标注。
- [ ] 内容：日期开场、自然过渡、结尾回顾；无常识科普堆砌、无文件树/CLI 代替设计。
- [ ] 制作：逐场景顺序渲染；每场景抽帧检查并修复重渲染。
- [ ] 规格：1080p30；60px 标点断行字幕 + 独立 SRT；配音参数符合要求；约 -16 LUFS。
- [ ] 封面：三尺寸齐备、第一名突出、各尺寸可读。
- [ ] 交付：MP4 + 三封面 + 简介齐备；"非 AI 类项目"名称全位置一致；缺项如实说明。
- [ ] （建议）完整播放成片复核：音画同步、字幕先后、黑帧、片尾截断、多音字与英文名读音。

保留一行验收结论，例：`榜单/来源已核对；场景抽帧已完成；全片复核[已完成/未完成]；备用配音[是/否]；已知局限[说明]`。

## 9. 失败分支

| 情形 | 处理 |
|---|---|
| 榜单不可用 / 项目不足 | 如实报告，不换榜；按实际数量制作并标明原因。 |
| 来源冲突 / 数据待核实 | 说明差异与未知；不虚构数字。 |
| MiniMax 异常 | 认证、额度或服务异常时换 `edge-tts zh-CN-XiaoxiaoNeural` 兜底，**交付时披露切换及影响**；仍失败则报告已完成环节与缺失产物。 |
| 环境 / 渲染失败 | 通过 conda-forge 恢复；画面问题修复后重渲染；部分成功先交成功的一期。 |

## 10. 安全与保密

- 不运行陌生仓库二进制和安装脚本。
- 文档与对外交付不包含密钥、token、账户详情或密钥文件路径。
